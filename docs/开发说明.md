# 开发说明

## 构建与打包

Node.js22+，先`npm ci`，再`npm run build`、`npm test`、`npm run package`。构建不依赖在线地图CDN或Cesium ion；第三方引擎与Worker随完整包提供。

主脚本、样式和运行资源由构建生成。打包前校验版本、构建收据和完整资源库存；安装ZIP含`FILES.sha256`。`dist/`输出安装、源码和虚构示例包；不要将个人仓库或旧Git历史混入项目。

`npm test`执行所有`.test.ts`与`.test.mjs`。安装事务测试需要Mac或提供`/bin/zsh`的兼容环境，仅操作系统临时目录的合成仓库。`test:recovery`和`test:installer`可单独运行。可选旧版对照需通过`TRAVEL_GLOBE_BASELINE_ROOT`指定三个旧生产模块的位置，不配置时明确跳过，不伪造旧历史。

## 素材重建

正常构建使用仓库内已校验的派生素材。`npm run assets:realistic`可从`assets/upstream/`中的NASA素材离线重建自然地表、云层和粗高程。

暗蓝素材重建：依据`assets/atlas/provenance.json`中的固定Natural Earth提交、原文件名和哈希，另行取得公开原始GeoJSON目录，运行：

```sh
node --import tsx scripts/build-atlas-assets.mjs /path/to/natural-earth-geojson
```

行政样本核验工具需显式提供元数据、样本清单和输出路径，不读取仓库外的私人资料，也不将结构可解析当成全球市域覆盖通过。

## 实际宿主测试

`node scripts/prepare-atlas-qa.mjs`创建只含虚构示例的临时仓库和配置目录。仅将其用于独立Obsidian测试实例，调试端口为本机9224。运行宿主脚本前设置`TRAVEL_GLOBE_QA_VAULT`为生成的临时vault，`TRAVEL_GLOBE_QA_DIR`为仓库外输出目录；守卫拒绝普通个人仓库路径。

可串行运行`qa-atlas.mjs`、`qa-atlas-edge.mjs`、`qa-cesium-regression.mjs`、`qa-recovery.mjs`。脚本共用同一宿主，禁止并行操作UI。冻结发行包验收还应从ZIP完整安装并逐项核对`FILES.sha256`，不能仅依赖临时目录版本号。
